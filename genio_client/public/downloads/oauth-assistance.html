🧭 Genio — Guide d'assistance OAuth
Google + GitHub · pas à pas avec liens directs

Objectif : créer les deux applications OAuth, renseigner 5 variables, redémarrer le service, puis tester une vraie connexion depuis votre navigateur. Aucun secret réel dans ce document — uniquement des exemples à remplacer.
Note d'honnêteté : les encadrés « schéma » ci-dessous sont des maquettes illustratives (je ne peux pas capturer vos consoles, elles exigent votre propre connexion). Les liens, eux, sont directs et officiels.

0 · Prérequis (2 minutes)

1
Un compte Google (pour Cloud Console) et un compte GitHub.
2
L'URL publique exacte du frontend Genio. Exemples de ce déploiement :
dev → http://localhost:8098
prod → https://genio.hitech.tn
3
Accès SSH/sudo à la machine Genio (pour poser les variables + redémarrer).

A · Google — créer le client OAuth

1
Ouvrez la console (connectez-vous avec votre compte Google) :
🔗 Console → Identifiants (Credentials)
Si aucun projet : « Select a project » → New Project → nommez-le genio → Create.
2
Écran de consentement OAuth (obligatoire avant le client ID) :
🔗 Écran de consentement
  • User type : External (ou Internal si Google Workspace).
  • Nom d'application : Genio · scopes : openid, email, profile uniquement.
  • Si External en mode Testing : ajoutez votre adresse Gmail dans Test users, sinon Google refusera votre propre connexion.
3
Retournez dans Credentials → Create Credentials → OAuth client ID, type Web application, puis ajoutez exactement cette URI (copiez-collez, sans espace ni slash final) :
SCHÉMA ILLUSTRATIF — champ « Authorized redirect URIs »
http://localhost:8098/api/v1/auth/oauth/callback
https://genio.hitech.tn/api/v1/auth/oauth/callback
4
Cliquez Create → copiez Client ID (finit par .apps.googleusercontent.com) et Client Secret (GOCSPX-… affiché une seule fois).
⚠ Ne les collez jamais dans le frontend, git ou un chat public — variables d'environnement serveur uniquement (§C).

B · GitHub — créer l'OAuth App

1

🔗 Nouvelle OAuth App GitHub
(ou : avatar → Settings → Developer settings → OAuth Apps → New OAuth App)
2
Remplissez exactement :
SCHÉMA ILLUSTRATIF — formulaire GitHub
Genio
http://localhost:8098
http://localhost:8098/api/v1/auth/oauth/callback
Register application → copiez le Client ID (Ov23…), puis Generate a new client secret (affiché une seule fois).

C · Poser les 5 variables + redémarrer

sudo -e /etc/systemd/system/genio.service.d/oauth.conf
# Collez (remplacez les xxxx par VOS valeurs copiées) :
[Service]
Environment=GENIO_GOOGLE_CLIENT_ID=1234567890-....apps.googleusercontent.com
Environment=GENIO_GOOGLE_CLIENT_SECRET=GOCSPX-....
Environment=GENIO_GITHUB_CLIENT_ID=Ov23....
Environment=GENIO_GITHUB_CLIENT_SECRET=....
Environment=GENIO_OAUTH_REDIRECT_BASE=http://localhost:8098
# GENIO_SESSION_TTL=604800   # optionnel (défaut 7 jours)

sudo systemctl daemon-reload && sudo systemctl restart genio.service
curl -s http://127.0.0.1:8000/api/v1/auth/oauth/google/start | head -c 120
# Attendu : {"ok":true,"auth_url":"https://accounts.google.com/..."}

D · Tester la vraie connexion (vous, dans votre navigateur)

1
Ouvrez Genio → cliquez « ادخل بـ Google » → complétez chez Google → retour auto sur /app?login=ok + prénom/avatar affichés.
2
Déconnectez-vous (bouton اخرج) → recommencez avec GitHub → autorisez → même vérification.
3
Envoyez-moi : ce que chaque étape a affiché (ok/erreur + libellé exact). Je vérifierai côté serveur : callback/state/PKCE/XSRF/session, isolation croisée, binding WebSocket.

F · Sécurité (rappels non négociables)

  • Secrets uniquement en variables d'environnement serveur — jamais frontend/git/chat/logs.
  • Une seule callback enregistrée par provider (celle du §A-3/§B) — le backend refuse toute autre.
  • Pas de liaison automatique Google↔GitHub par email : même adresse = deux comptes séparés.
  • Docs officielles : OpenID Connect Google OAuth Apps GitHub
  • App Google créée + redirect URIs exactes
  • App GitHub créée + callback URL exacte
  • 5 variables posées + restart + /start → auth_url
  • Login Google réel OK (nom/avatar affichés)
  • Logout OK · Login GitHub réel OK
  • Résultats envoyés pour vérification serveur finale
