# Process Monitoring & Troubleshooting

## 1. الشرح التقني
السيرفر راي ينزلل ولا يعرف شنو اللي جفل. نعيهاش ونحاولوش. الـ process ميت أو يبطّش الـ CPU/YOLO.

## 2. تفصيل الأوامر
```bash
ps auxf    # الشهادة الكاملة: user، الـ PID والـ PPID، الـ CPU% والـ MEM%
top -bn1   # نفس المعلومة في تقرير حقيقي — الأرقام تتحرك ونشوف اللي يصرف.
htop       # top نمطغيّرнее: Python مكتبة الـ CLI التي تقفلو الألية بال눌ّوات.
kill <PID> # والسؤال: شنو إذا كانش يموش؟
kill -9 <PID>  # هاذا المذنب يجبرو — باش نتأكدو من الفكرة.
```

## 3. سيناريو Self-Healing
السيرفر مرهّب: `ssh` يجيب "Permission denied". أشرحلي المخاطر التي يجب الانتباه لها.
1. تحقق من المستخدم: `whoami` و `id`.
2. تحقق من المجلات: `ls -al ~/.ssh` — نربوطو على الملفات باش نضيف `.pub` لوحده.
3. تحقق من الصلاحيات: المجلّة سحرة الـ 700 والـ key الـ 600.
4. إذا كان الـ sshd ميت: `sudo systemctl status sshd` — شوف `ExecStart` باش تعرفو على الـ config المفقود.
الحل الجذري: نضيف الـ key بالاسم الصحيح `ssh-add ~/.ssh/id_ed25519` ثم نضبط `UseKeychain no` في الـ config.

## 4. تمرين المخبر
1. شوف الأماكن التي يعيّن فيها النظام الـ PID: `/var/run` و `/proc`.
2. كيفاش نتأكدو من المهام الممطورة؟ `ps aux | grep -E 'python|scrapy'`.
3. إذا كان الشغّال مطغوط، كنا نضيفو الـ & باش يعاودوا يعملوا في الخلف: `python crawl.py > out.log 2>&1 &`.
4. المراجعة: شوف `jobs` و `bg/fg` باش تعرفو على الأداء البياني.
