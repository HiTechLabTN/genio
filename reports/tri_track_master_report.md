### 1.2 Training script: `scripts/train_gemma4_qlora.py`

12 GB-VRAM-tuned QLoRA recipe (engines: `trl` SFTTrainer, `trainer` native fallback,
`unsloth` auto-disable on this host):

- **Quantization**: BitsAndBytes 4-bit NF4, `double_quant=True`,
  compute dtype bf16, quant-storage bf16.
- **LoRA**: `r=16`, `alpha=32`, dropout 0.05, target modules
  `q_proj, v_proj, k_proj, o_proj, embed_tokens` (task specified set), task CAUSAL_LM.
- **Memory**: `per_device_train_batch_size=1`, `gradient_accumulation_steps=4`,
  gradient checkpointing ON, `paged_adamw_8bit`, `max_seq_len=1024`.
- **Preflight** (`--dry-run`) performs architecture/GPU/bnb checks and prints the
  memory envelope without downloading weights.

**QLoRA memory envelope** (computed, verified in dry-run):

| Component | GB |
|-----------|----|
| 4-bit NF4 weights (12B) | 6.00 |
| Activations (grad-checkpointed, 1024 ctx) | 1.60 |
| paged AdamW 8-bit optimizer | 0.15 |
| Gradients | 0.01 |
| CUDA/kernel reserve | 0.40 |
| **Peak estimate** | **8.16 GB (70% of 11.63 GB usable)** |
| Trainable LoRA params | 12.3 M (**0.10%** of model) |
| **Fits 12 GB?** | **yes** |

**Execution blocker found**: `google/gemma-4-12B-it` advertises architecture
`gemma4_unified`, which transformers 5.5.0 does not ship yet
(needs ≥ transformers 5.6-nightly, or `trust_remote_code` equivalents —
AutoConfig currently rejects it). Additionally **Unsloth 2026.8.22 import fails
on Python 3.10** (`torchcodec` `.so` ABI break). Script is therefore 100%
ready on config/math and will run unchanged after a transformers upgrade;
fallback path documented in the script header.
